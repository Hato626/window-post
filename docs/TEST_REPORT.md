# 窗口邮局 1.0 验收报告

验收日期：2026-10-15。状态：本地规则测试与真实浏览器流程通过。GitHub CI 定义已提供；远程 CI 结果以仓库运行记录为准。

## 环境与结果

- Windows，Node.js，Microsoft Edge 155.0.4283.45（Playwright 驱动，真实浏览器引擎）。
- `npm test`：13 项测试通过。
- `npm run test:ui`（指定 Edge channel）：10 个验收流程通过，0 个浏览器脚本异常。
- 1366×768 和 1024×768 视口：没有横向溢出，发件和单步控制在初始可视区内。页面可纵向滚动。
- 直接 `file://` 打开 `index.html` 可运行，测试未依赖 HTTP 服务来绕过游戏的离线启动。
- 独立验收人员另行手动布置第一关、拖拽和撤销、发件通关、刷新恢复、拒绝坏 JSON、编辑副本后保存并重新通关，均通过。

## 规则验收

1. 24 个内置关卡结构有效、参考布局可解、初始布局未完成，覆盖全部六种工具。
2. 所有 24 关的实际目标，与独立手写的设计期望逐个比较；避免仅用同一套生成函数证明自身正确。
3. 每一回放帧中的位置严格对应信件路线；到站后保持最后位置。
4. 持续覆盖只加工一次；离开再进入可重复加工。
5. 同时进入的窗口遵守列表顺序；不同入口时刻遵守真实路径顺序。
6. 相向路线得到相反邮戳顺序。
7. 翻面、擦除、邮戳方向记录和折痕上限符合独立断言。
8. 重放确定，不修改关卡、布局和先前回放帧。
9. 撤销 / 重做恢复独立值，新的修改清空重做分支。
10. 存档往返一致，篡改工艺的布局和异常存档被拒绝。
11. 编辑器目标生成与 JSON 往返产生可解关卡。
12. 超界、重复标识、非法类型、非相邻路径、非法状态和过大输入被拒绝。
13. 窗口边界采用左上包含、右下排除，避免相邻窗重复覆盖边界。

## 浏览器验收流程

1. 1366×768 启动并检查主要操作可见。
2. 实际鼠标拖动窗口、拖动缩放角、撤销、重做。
3. 手工布置第一关，播放、暂停、单步，继续并通关。
4. 刷新恢复布局和通关记录。
5. 第 15 关相向路线，通过界面加载参考布局并逐步运行至完成。
6. 1024×768 检查没有横向溢出，发件控制可见。
7. 编辑器添加 / 删除工具、绘制新路线、生成订单、保存后重新游玩。
8. 实际下载关卡文件、上传导入；异常文件被拒绝且保留当前关卡。
9. 存档文件导出 / 导入往返，整个流程无 pageerror。
10. 不通过服务器，直接打开发行入口并操作窗口。

测试过程的截图和 JSON 结果由脚本输出到未纳入版本控制的 `artifacts/`。README 截图是受控游戏测试场景。

## 边界与未覆盖部分

- 这是离线 Web 游戏，不包含原生桌面安装器；双击入口由系统默认浏览器打开。
- 本轮实际浏览器验收使用 Windows Edge。Firefox、Safari 和移动设备未做同等完整验收。
- 仅布局变更支持撤销；编辑器的工具列表结构和路线绘制操作不进入布局撤销栈。
- 浏览器文件来源存储策略会影响自动保存，始终可通过游戏内 JSON 导出 / 导入备份。
- 图形编辑器不直接编辑原始信件的双面颜色，保留所复制关卡的原始状态；JSON 格式可描述这些状态。
- 页面支持键盘移动和表单操作；自由绘制路线与窗口缩放需要指针设备。
- “全部通过”指以上明确列出的验收范围，不代表已穷尽所有浏览器和任意自制数据的组合。
